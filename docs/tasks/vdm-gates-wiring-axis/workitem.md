# Ось рубрики: гейты vdm проволочены через принятый в репозитории фреймворк

> Пришло по intercom от `ai-dev-plugins` (31.08.2026), промоучено в кристалл
> 01.09.2026. Полный исходный бриф — `references/intercom-brief.md`.
> Работа **не горит**: отправитель сам измерил цену дыры и она нулевая.

## Назначение

Добавить в рубрику vdx ось, которая проверяет: **если в репозитории
используется `vdm`, его pre-commit гейт проволочен через тот hook-фреймворк,
который в этом репозитории принят, и реально резолвится**.

Постановка сознательно сформулирована как «проволочено тем, что тут принято»,
а не «поставьте `.githooks`» — какой фреймворк принять, решает репозиторий.

**Почему это к vdx, а не к vdm.** «Проволочен ли репозиторий как надо» — вопрос
о качестве репозитория, то есть предмет vdx. Задача `vdm` — дисциплина
воркайтемов, а не гигиена чужих репозиториев. У `vdm` три поверхности
энфорсмента, и только третья требует ручной установки:

| Слой | Где живёт | Ставится ли |
|---|---|---|
| `PreToolUse` completion-guard | `plugins/vdm/hooks/hooks.json` | харнесс сам |
| `PostToolUse` crystal-lint | там же | харнесс сам |
| pre-commit бэкап | `crystal-precommit-check.sh` (в `vdm-git`) | **вручную, в три шага** |

Ось касается только третьей строки.

**Критерий успеха** — семь acceptance criteria в `## Next actions`. Ключевой из
них: проверка не должна быть зелёной, когда сниппет хука присутствует, но
переменная окружения не задана и скрипт не резолвится. Сегодняшняя активация
гейта — это `core.hooksPath` + файл хука + переменная с абсолютным путём к
скрипту; документированный сниппет **без переменной молча ничего не делает**,
то есть отказывает неотличимо от успеха.

## Текущая модель

**Срочности нет, и это измерено, а не предположено.** Read-only аудит отправителя
28.08.2026: 371 воркайтем в 12 репозиториях, проволоченный git-хук — в 1 из 12,
нарушений инварианта `status: done` при непогашенных `- [ ]` — **0**. Единственный
downstream-бэкап проверяет ровно этот инвариант; установленный во все 11
репозиториев, он не поймал бы ничего. Два ассистент-хука справляются.
«Ось не нужна вовсе» отправитель явно называет допустимым ответом.

**Три утверждения брифа проверены по коду и два из них неверны** (DL #2–#4):

- `command_succeeds` — **заглушка**, не escape-hatch. Вариант №1 из брифа отпадает.
- Рекурсивного глоба в `expandPaths` нет — только `dir/*.ext`.
- `git_hook_installed` проверяет лишь наличие файла/записи, не резолвится ли
  скрипт, и не знает про `core.hooksPath`. Переиспользовать нельзя, надо переписать.

**Ось `git-hygiene` не подходит как место для проверки**: она `class: supporting`,
без `applies_when`, применяется везде. Нужна отдельная ось с `applies_when`.

**Практическое препятствие из брифа снято** (DL #5): esbuild пересобран,
`npm run vdx` работает.

**Открытый вопрос — один**: чем опознать присутствие `vdm` в репозитории для
`applies_when`. `.claude/vdm-plugins.json` есть в 1 репозитории из 12, и это
следствие zero-config дизайна, а не небрежность. Надёжное свидетельство —
наличие `tasks/` с файлами `workitem.md` на произвольной глубине. С учётом
DL #2 и DL #4 это означает новый предикат с обходом дерева.

**Объём работы**: новый предикат обхода дерева + переписанный
`git_hook_installed` + новая ось в canonical-рубрике + 3 теста + bump рубрики
до v0.4.0 (minor — новая ось).

## Decision Log

### #1 / 2026-09-01 / Промоутить в кристалл, а не делать сейчас и не отклонять

**Source:** user
**Basis:** user-stated
**Basis-detail:** Дмитрий выбрал «Промоутить в кристалл» из трёх предложенных
вариантов (сделать сейчас целиком / промоутить / отклонить и заархивировать).
Отдельным ответом — «Да, починить» про блокер esbuild.
**Context:** Бриф от `ai-dev-plugins` явно снимает срочность и явно разрешает
ответ «ось не нужна». Измеренная цена дыры — 0 пойманных нарушений на 371
воркайтеме. При этом объём работы — новый предикат + переписанный
`git_hook_installed` + ось + тесты, то есть не инлайн-правка.
**Why:** Работа реальная и специфицированная (7 acceptance criteria), но
ценность на сегодня не подтверждена данными. Оба крайних варианта хуже:
делать сейчас — тратить на ось, которую никто не смотрит, вперёд других осей;
отклонить — потерять проработанную постановку, которую отправитель собирал
с аудитом на 12 репозиториев. Воркайтем сохраняет постановку, не занимая слот.
**Implication:** Кристалл заводится в **Mode B (parking)**, `status: ready`,
без TaskCreate. Singleton не расходуется.

### #2 / 2026-09-01 / `command_succeeds` недоступен — вариант №1 из брифа отпадает

**Source:** assistant
**Basis:** observed
**Basis-detail:** Прочитан `cli/src/predicates.ts:156` — тело предиката целиком:
`command_succeeds: () => { warnOnce('command_succeeds'); return false; }`.
`warnOnce` (строка 20) печатает `predicate "..." not implemented in v0.1 —
returning false`. Подтверждено `cli/README.md:103`. Спека
(`docs/specs/rubric-format.md:195`) описывает предикат как существующий —
расхождение спеки с реализацией.
**Context:** Бриф предлагает три варианта для `applies_when` и называет первый —
`command_succeeds` с `find . -name workitem.md` — тем, что «уже есть в библиотеке,
работает сегодня».
**Why:** Утверждение брифа неверно фактически. Предикат всегда возвращает `false`,
то есть ось с таким `applies_when` не применилась бы **никогда** — и отказывала
бы молча, ровно тем способом, который сам бриф называет главным дефектом,
которого надо избежать.
**Implication:** Вариант №1 вычёркивается. Вариант №3 (маркер-файл) бриф
отклоняет сам как противоречащий zero-config. Остаётся вариант №2 — новый
предикат. Решение по его имени и сигнатуре — открытое, см. `## Next actions`.

### #3 / 2026-09-01 / `git_hook_installed` придётся переписать, а не переиспользовать

**Source:** assistant
**Basis:** observed
**Basis-detail:** Прочитан `cli/src/predicates.ts:103–113`. Тело проверяет ровно
три вещи: `fileExists('.husky/<hook>')`, regexp `^<hook>:` в `.lefthook.yml` /
`lefthook.yml`, и `composer.extra.hooks[hook]`. Ни резолва пути к скрипту, ни
чтения `core.hooksPath`, ни `.githooks/` в коде нет.
**Context:** Бриф опирается на существование `git_hook_installed` как на актив
(«у vdx уже есть предикат, знающий про husky / lefthook / composer-git-hooks»)
и предполагает, что ось строится поверх него.
**Why:** Предикат наследует ровно тот дефект, от которого бриф требует
избавиться: он зелёный при наличии файла безотносительно того, резолвится ли
скрипт. Плюс он не покрывает `core.hooksPath` + `.githooks/` — а гейт `vdm`
активируется именно так. Критерий «не зелёная, когда переменная не задана»
недостижим на текущей реализации.
**Implication:** В объём входит переписывание `git_hook_installed` (или новый
предикат рядом) с (а) распознаванием `core.hooksPath`, (б) проверкой привязки
к событию `pre-commit`, (в) проверкой существования пути к скрипту.
Переписывание существующего предиката — потенциально breaking для чужих рубрик,
это отдельное решение при реализации.

### #4 / 2026-09-01 / Рекурсивного глоба в библиотеке фактов нет

**Source:** assistant
**Basis:** observed
**Basis-detail:** Прочитан `expandPaths` в `cli/src/facts.ts:171–194`. Разбирается
единственная форма — regexp `^([^*]+)\/\*\.(.+)$`, то есть `dir/*.ext`, один
уровень, через `readdirSync` без рекурсии. `**` не поддерживается. `has_file`
(`predicates.ts:41`) берёт фиксированный путь.
**Context:** Бриф отмечает, что «`has_file` берёт фиксированный путь, глоб не
выразить», и предлагает новый предикат `has_file_matching` / `has_path_glob`
как «чище, но это расширение библиотеки».
**Why:** Уточнение масштаба: это расширение не только реестра предикатов, но и
слоя фактов — нужен обход дерева с исключениями (`node_modules/`, `vendor/`,
скрытые сегменты), а не добавление паттерна в существующий `expandPaths`.
Оценка «чище, но расширение» в брифе занижает объём.
**Implication:** Вариант №2 стоит дороже, чем звучит в брифе. Это не меняет
вывод (вариант №1 всё равно недоступен, DL #2), но влияет на приоритет: ось
без подтверждённой ценности требует нового обхода дерева в `facts.ts`.

### #5 / 2026-09-01 / Блокер esbuild снят

**Source:** both
**Basis:** observed
**Basis-detail:** До: `npm run vdx -- --version` падал с `TransformError` в
`node_modules/esbuild/lib/main.js:2029` (`generateBinPath`) — бинарь под другую
платформу, машина `x86_64`. После `npm rebuild esbuild` в `cli/` — та же команда
печатает usage-блок. Оба запуска выполнены в этой сессии.
**Context:** Бриф называет это «первым, обо что вы споткнётесь». Дмитрий выбрал
«Да, починить» отдельным ответом.
**Why:** Чинится за одну команду и блокирует любую работу в репозитории, не
только эту ось — держать блокер ради чистоты границ задачи смысла нет.
**Implication:** Из постановки уходит раздел «практическое препятствие».
Починка не закоммичена — `node_modules/` не под версионным контролем, и на
`npm ci` проблема вернётся (см. Sidetrack #3).

## Sidetracks

### #1. `cli/README.md:103` устарел — `config_value` больше не заглушка

**Возникло в:** проверке DL #2 (грепал `command_succeeds` по репо)
**Описание:** Строка гласит `config_value`/`command_succeeds` predicates are
stubs (warning at evaluation). Для `command_succeeds` это верно, для
`config_value` — уже нет: `predicates.ts:115–154` реализует его полностью, с
операторами `present`/`equals`/`gte`/`matches`. Читатель README получает
неверную картину доступных предикатов.

**Status:** open

### #2. `docs/specs/rubric-format.md:195` описывает `command_succeeds` как рабочий

**Возникло в:** проверке DL #2
**Описание:** Таблица предикатов в спеке содержит строку
`command_succeeds | cmd | escape-hatch, sandboxed shell` без пометки, что
предикат не реализован. `docs/specs/drift-algorithm.md:137` тоже говорит о нём
как о «последней линии защиты». Именно на это утверждение спеки опёрся автор
брифа, предлагая вариант №1 — то есть расхождение спеки с реализацией уже
стоило одной неверной рекомендации во внешнем репозитории.

**Status:** open

### #3. esbuild сломается снова на `npm ci`

**Возникло в:** DL #5
**Описание:** `npm rebuild esbuild` чинит текущее дерево `node_modules/`, но не
лечит причину — платформенный бинарь подтягивается опциональной зависимостью.
Чистая установка на этой машине воспроизведёт `TransformError`. Стоит проверить,
не зафиксирована ли в `package-lock.json` платформа другой машины.

**Status:** open

### #4. `vdx --version` печатает usage вместо версии

**Возникло в:** верификации DL #5
**Описание:** `npm run vdx -- --version` выводит usage-блок. Флаг либо не
реализован, либо не распознан и падает в default-ветку. Мелочь, но `--version`
— первое, что набирают при диагностике.

**Status:** open
