# Память Claude внутри проекта

> Из письма nas-info `vdx/claude-memory-in-project` (intercom, 2026-10-22): решение
> владельца перенести память агента внутрь проектов, проверкой при запуске
> `vdx ai`, и потом свободно переносить папки проектов.

## Назначение

**Боль.** Claude Code держит память проекта и его транскрипты в
`~/.claude/projects/<путь проекта, не-буквы → «-»>/` — по физическому пути
папки. Перенёс папку — память и история разговоров остались под старым путём,
продолжение разговора пропало. Владелец давно хочет переложить проекты global
auth внутрь `GA/`, а всё про space/limeflow — в `SPACE`; путь на всех машинах
будет один, `/Volumes/Working/…`.

**Слово владельца** (письмо nas-info, 2026-10-22): «В некоторых проектах я
перенёс память внутрь. Просто сделаем это проверкой при запуске vdx ai, и ты
составишь список, где мне надо запустить команду, чтобы провести миграцию до
переноса папок — всех, и PhpStorm Projects, и AI Projects»; о транскриптах — «да,
ты прав, транскрипты тоже». Список проектов nas-info владельцу уже дал.

**Что просит nas-info.**
1. Проверка при запуске `vdx ai`: `autoMemoryDirectory` — это
   `<корень проекта>/.claude/memory/`, каталог памяти по умолчанию для текущего
   пути пуст; иначе строка и команда, которая исправит. Верным должен быть файл
   настроек, не только флаг запуска: сессии не через vdx (`claude -p` из
   echelon) читают только файлы.
2. Команда миграции одного проекта: заметки из каталога по умолчанию — в
   `.claude/memory/`, настройку записать. Одинаковое имя с разным содержимым — не
   перезаписывать; старый каталог переименовать, не удалять. Остатки после
   прежнего ручного переноса — global-auth-gap, t23b-content, t23b-program.
3. Перенос проекта: каталог транскриптов переименовать под новый путь, на одной
   машине (вторая получит через Syncthing). Глагол или часть проверки — за vdx.
4. Проекты без git (space-team, steven-maslavets, avatar, l10inc) — правило за vdx.

**Критерий готовности.** На выпущенном CLI: `vdx ai` в проекте, чья память не в
проекте, называет это и команду; команда переносит память без потерь; после
переноса папки `vdx ai` возвращает проекту память и разговоры; владелец получил
список команд по проектам; nas-info — ответ.

## Текущая модель

**2026-10-23: выпущено в 0.37.0 (`6b28794`), сет v1.7.0 (`383ffc3`); на lft и m3 —
0.37.0.** В 0.37.0 вопрос «под git?» в `vdx doctor --fix` звучит, только когда и stdout
— терминал: со stdout в `/dev/null` (скрипт владельца) он пропускался, и память
оставалась вне git — исправлено в 0.37.1 (stdin и stderr), в живом терминале не
проверено. 541 юнит и 6 e2e, `check` чистый. Как Claude Code 2.1.308 читает

папке; флаг `--settings` важнее обоих. Поэтому путь в файле абсолютный, и после
переноса папки он — след старого места.

  пользовательских.
- **Где память** (DL #3, #4, #7): всегда `.claude/memory/`. Личный проект — без
  `origin` или `origin` на хосте из `git.personal_hosts` профиля (у владельца —
  git.vorobyev.name): память под git, путь в `.claude/settings.json`. Остальные:
  путь в `.claude/settings.local.json`, память вне git (`/.claude/memory/` в
  `.git/info/exclude`), под git — только по «да», Enter и без терминала — нет.

  `projects/<старый путь>` → `projects/<новый>`; если новый уже есть — переносятся
  отсутствующие файлы, остальное откладывается в `.moved-<дата>`.
- **Где видно** (DL #6): `vdx doctor` — строка `Claude memory`; `vdx doctor
  --check` — строка для сессии (хук плагина) с командой и, где нужно, «сессия

### #2 / 2026-10-22 / Как Claude Code 2.1.308 находит каталог памяти

**Source:** assistant
**Basis:** observed
**Basis-detail:** код в бинаре `/usr/local/Caskroom/claude-code@latest/2.1.308/claude`
(lft, 2026-10-22; поиск по `autoMemoryDirectory`, копия не сохранялась — бинарь
стоит на станции и читается тем же поиском). Схема настройки: «Custom directory
path for auto-memory storage. Supports ~/ prefix for home directory expansion.
Ignored if set in projectSettings (checked-in .claude/settings.json) for security.
When unset, defaults to ~/.claude/projects/<sanitized-cwd>/memory/». Код
противоречит второй фразе: источники — `policySettings`, `flagSettings`, затем
`localSettings` и `projectSettings`, только если `HM()`, затем `userSettings`;
первый непустой выигрывает. `HM()` — `_e()` или `Ls()`; что это «режим `-p`» и
«папка доверена» — вывод по соседнему тексту («no workspace trust record counts in
this process…»), не проверено. Путь: `~/` раскрывается в домашний каталог, затем
нормализуется; отвергается не абсолютный, короче 3 символов, буква диска, с NUL.
Переменных (`$CLAUDE_PROJECT_DIR` и т. п.) нет. В окне доверия к папке — «This
folder changes where automatic memory is written (autoMemoryDirectory), declared
in …». `transcript_relocated` в бинаре — у `/cd` (перенос идущей сессии в другую
папку, `set_cwd`), не у папки, перенесённой снаружи. Замер nas-info (`claude -p
--settings`): относительный путь молча отброшен, абсолютный принят; память и
транскрипты из папки через симлинк — под путём цели.
**Context:** можно ли записать путь, который переживёт перенос папки.
**Why:** нельзя: ни относительного пути, ни переменной Claude Code не принимает, а
`~/` после переноса в `/Volumes/Working` тоже устареет.
**Implication:** путь в файле настроек абсолютный, и проверка сравнивает его с
текущим корнем; флаг `--settings` от `vdx ai` перекрыл бы файл, но `claude -p` не
через vdx его не получит (п. 1 письма).
