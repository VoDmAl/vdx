# Обзор аналогов и build-vs-adopt

Статус: **верифицировано** через web-research 2026-05-22 (3 параллельных агента).
Для каждого инструмента указано **что он делает** и **чего НЕ делает** —
это то, что превращает чужой инструмент в кусочек «комбайна» или показывает gap,
который vdx обязан закрыть.

Полные находки — в [decisions.md](decisions.md) N5–N9.

---

## A. Раннеры задач (столп P1)

| Инструмент | Что делает | Чего НЕ делает | Вердикт |
|-----------|------------|----------------|---------|
| **mise** (jdx/mise) | Tasks stable (с 2025). Полиглот by design. Делегирование через shell-shim'ы. JSON-discovery `mise tasks ls/info --json`. DAG-зависимости + parallel exec. Управление версиями тулинга. Env vars. | Cross-repo / shared-infra зависимости. Нормализованный словарь глаголов между проектами. | **Оседлать** (D3). Покрывает ~70% P1. |
| **Task** (go-task) | Зрелый YAML-раннер. `includes`. `--list --json`. | Управление версиями тулинга. Stack-detection. | Запасной #2 |
| **just** | Минималистичный justfile-runner. `--list`. | Машиночитаемые метаданные слабые. Управление версиями. | OK, слабее по discovery |
| **moon** v2.0 (май 2026) | Полиглот toolchains, project graph, кеширование, WASM-плагины. | Лёгкая работа с отдельными репозиториями — заточен под монорепо. | Не та форма |
| **make** | Универсален, есть везде. | Discovery API (парсить `.PHONY` хрупко). Полиглот плохо. Управление версиями. | Только цель делегирования |

**Пример использования mise в vdx:** задача `up` в `mise.toml` — это одна строка
`run = "npm run docker:up"` / `"composer up"` / `"make up"`. Раннер становится
*слоем именования*, проектную логику переписывать не нужно.

## C. Аудит зрелости (столп P2)

Сбор фактов — оседлать; рубрику и drift-движок — строить.

| Инструмент | Что делает | Чего НЕ делает | Вердикт |
|-----------|------------|----------------|---------|
| **OpenSSF Scorecard** | 18+ security/supply-chain probes. Структурный JSON через `--probes`/`--format probe`. Работает на любом репо локально. | Code quality, наличие тестов, phpstan level, общий рубрикатор. | **Оседлать** для security-осей. Архитектурный паттерн «probes → JSON → policy» взять целиком. |
| **Qlty CLI** (qltysh/qlty) | Преемник CodeClimate Quality. Code quality + smells + metrics. 40+ языков. Локально, без Docker/аккаунта. SARIF/JSON. | Versioned org rubric. Drift. Scaffolding fixes. | **Оседлать** для code-quality фактов |
| **MegaLinter** | Запуск 50+ линтеров одним прогоном (Docker). Reports. LLM Advisor. | Versioned rubric. Drift. Scoring как уровень. | **Оседлать** как движок запуска линтеров |
| **trunk check** | Meta-линтер. Hold-the-line (только changed files). Кеширование. | Web-приложение Code Quality **закрыто 27.07.2025**. Versioned rubric. Drift. | Опционально |
| **Repolinter** | (был) Декларативные YAML-assertions про репозиторий. | **АРХИВИРОВАН** — обновлений нет. | Не брать. Только референс дизайна ruleset |
| **Backstage Soundcheck** | Tracks/Levels/Certifications. Fact collectors. Checks. | **Версионирование checks / drift** против прошлой версии стандарта. Локальный запуск. Чужие репы (catalog-bound). | Прецедент концепции; недоступен как backend |
| **Cortex / OpsLevel / Port** | Enterprise scorecards. Maturity levels (Bronze/Silver/Gold). | Локальный запуск. Чужие репы. Non-SaaS использование. | SaaS, не подходит как backend |
| **SonarQube** | Quality gates, «Clean as You Code» (new-code focus). | Versioned org-rubric с drift поверх метрик. Кросс-репо стандарт. | Одна ось + UX-прецедент drift |
| **CodeScene** | CodeHealth behavioral. MCP-интеграция. | Open-source / локальный бесплатный. Rubric / drift. | Опциональная премиум-ось |

| Инструмент | Что делает | Чего НЕ делает | Вердикт |

## Вывод

Связки vdx как единого продукта **не существует**. Готовое закрывает: раннер
(mise), сбор фактов (Scorecard / Qlty / MegaLinter), scaffold-fix (copier),
транспорт для агента (MCP). **vdx собирается как «комбайн»**; собственный код —
только то, чего нет ни у кого:

1. Нормализованный словарь глаголов поверх mise.
2. Версионируемая рубрика + drift-движок.
3. Shared-infra оркестрация.
4. Структурированный исполняемый манифест.

Принятые решения D3–D6 и итоговая рекомендация — в [decisions.md](decisions.md)
и [decision.md](decision.md).
